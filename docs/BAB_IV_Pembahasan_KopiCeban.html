BAB IV: PEMBAHASAN

4.1 Hasil Implementasi Sistem

Pada tahap ini dilakukan pembahasan hasil implementasi aplikasi web pemesanan kopi Its By Me Coffee (repo kopi-ceban) yang dibangun menggunakan Next.js, React, TypeScript, Prisma, dan PostgreSQL. Implementasi mencakup dua sisi utama, yaitu sisi pelanggan (customer) untuk proses pemesanan, dan sisi pengelola (admin) untuk operasional bisnis. Selain itu, sistem juga terintegrasi dengan Midtrans untuk pembayaran non-tunai, serta mendukung pembayaran tunai dengan mekanisme validasi waktu.

Secara umum, hasil implementasi telah memenuhi kebutuhan proses bisnis kedai kopi modern, mulai dari publikasi menu, transaksi pesanan, pemilihan metode pembayaran, monitoring status pesanan, hingga analitik transaksi dan pengelolaan meja pada area dine-in.

4.2 Implementasi Antarmuka Sisi Pelanggan

4.2.1 Halaman Beranda

Halaman beranda menjadi titik masuk utama pengguna sebelum melakukan pemesanan. Pada halaman ini ditampilkan identitas brand, nilai jual utama, ringkasan statistik layanan, tombol ajakan pemesanan, serta peta lokasi kedai berbasis Google Maps. Navigasi diarahkan ke halaman menu dan halaman pemesanan sehingga alur pengguna tetap sederhana dan terarah.

4.2.2 Halaman Menu Publik

Halaman menu menampilkan seluruh daftar produk kopi dari basis data secara dinamis, lengkap dengan foto, harga, deskripsi singkat, dan status ketersediaan stok. Item yang tidak tersedia ditandai secara visual sebagai habis, sehingga pengguna mendapat informasi stok sebelum menuju proses checkout. Pendekatan ini menurunkan potensi pesanan gagal akibat ketidaksesuaian stok.

4.2.3 Halaman Pemesanan, Pencarian, dan Filter

Pada halaman pemesanan, pengguna dapat melakukan pencarian menu, memfilter berdasarkan kategori/harga/ketersediaan, serta melihat rekomendasi menu. Interaksi keranjang didukung drawer yang responsif, sehingga pengguna desktop maupun mobile tetap memperoleh pengalaman transaksi yang konsisten. Sistem juga mendukung alur pemindaian QR meja dengan parameter table agar nomor meja dapat terisi otomatis untuk skenario dine-in.

4.2.4 Proses Checkout dan Metode Pembayaran

Form checkout mengumpulkan data nama pemesan, catatan pesanan, tipe order (dine-in/take-away), pemilihan meja, serta metode pembayaran (cash/transfer). Pada pembayaran transfer, sistem membuat transaksi Midtrans Snap dan menampilkan popup pembayaran. Pada pembayaran cash, sistem langsung membuat order berstatus PENDING dengan instruksi pembayaran di kasir. Proses ini memisahkan alur transaksi non-tunai dan tunai secara jelas tanpa mengganggu pengalaman pengguna.

Jika pembayaran berhasil, pengguna dapat melihat kuitansi dan mengunduh bukti transaksi (PDF/PNG) serta mencetaknya. Untuk pesanan cash, sistem menampilkan hitung mundur 15 menit; jika waktu habis dan belum dikonfirmasi, order berubah menjadi EXPIRED.

4.3 Implementasi Antarmuka Sisi Admin

4.3.1 Login dan Otorisasi Admin

Panel admin diakses melalui autentikasi berbasis NextAuth credentials provider. Kredensial diverifikasi terhadap data admin pada basis data dengan hash bcrypt. Middleware membatasi akses seluruh rute /admin agar hanya sesi terautentikasi yang dapat masuk. Dengan mekanisme ini, data transaksi dan fitur operasional terlindungi dari akses publik.

4.4 Implementasi Backend dan Integrasi Pembayaran

4.4.1 Struktur Data

Basis data menggunakan PostgreSQL dengan ORM Prisma. Entitas utama terdiri dari Admin, Menu, Order, PaymentLog, dan Table. Status order dikelola dengan enum (PENDING, SUCCESS, EXPIRED, FAILED, REFUNDED), sedangkan status meja menggunakan enum (AVAILABLE, RESERVED, OCCUPIED, CLEANING). Desain ini mempermudah validasi proses bisnis dan konsistensi data.

4.4.2 Alur API Pembuatan Order

Pada endpoint pembuatan order, sistem melakukan validasi input, validasi status meja, dan perhitungan ulang harga di sisi server agar total transaksi tidak bisa dimanipulasi dari sisi klien. Sistem menambahkan PPN 11% sebelum menyimpan data order. Untuk transfer, endpoint akan menghasilkan token Midtrans Snap; untuk cash, sistem langsung mengembalikan kode order untuk proses pembayaran di kasir.

4.4.3 Notifikasi Midtrans dan Sinkronisasi Status

Endpoint notifikasi Midtrans menerima callback perubahan status pembayaran, memvalidasi signature, mencatat jejak audit ke tabel payment log, lalu memperbarui status order. Ketika pembayaran sukses pada order dine-in, status meja berubah menjadi occupied; saat order gagal atau kedaluwarsa, meja dikembalikan ke available. Mekanisme ini membuat sinkronisasi pembayaran dan operasional meja tetap konsisten.

4.4.4 Mekanisme Auto-Expire untuk Cash

Sistem menyediakan endpoint khusus untuk menandai order cash sebagai expired jika melewati batas 15 menit dalam status pending. Fitur ini dapat dipanggil secara berkala (misalnya cron) dan juga didukung pengecekan langsung dari halaman pelanggan. Dengan demikian, antrian order tidak menumpuk oleh transaksi tunai yang tidak dilanjutkan.

4.4.5 Ekspor Data dan Upload Berkas

Untuk kebutuhan administrasi, data riwayat transaksi dapat diekspor dalam format CSV berdasarkan filter tertentu. Sistem juga memiliki endpoint upload gambar untuk kebutuhan manajemen menu, dengan keluaran URL relatif yang langsung bisa digunakan pada antarmuka.

4.6 Kesimpulan Bab

Hasil implementasi menunjukkan bahwa aplikasi web pemesanan kopi pada repo kopi-ceban telah berjalan secara end-to-end, baik dari sisi pelanggan maupun admin. Integrasi proses menu, pemesanan, pembayaran, manajemen meja, serta pelaporan transaksi telah saling terhubung dengan baik. Dengan demikian, sistem telah memenuhi kebutuhan operasional dasar kedai kopi digital dan siap dikembangkan lebih lanjut pada aspek otomatisasi laporan, penguatan keamanan, serta perluasan fitur loyalitas pelanggan.
